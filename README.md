# 케이터링 행사 운영

ZIP에는 빌드된 `dist`가 포함되어 있습니다. Node.js 24 이상이 설치된 컴퓨터에서 압축을 풀고 `node server/index.mjs`를 실행하면 의존성 설치 없이 http://127.0.0.1:3001 에서 사용할 수 있습니다. 소스를 수정해 다시 빌드할 때는 아래 설치 절차를 따르세요.

기물관리에서는 관리자가 카테고리(예: 웨딩)를 만들고 기물 이름·보유 수량·단위·메모를 등록할 수 있습니다. 기물 수정에서 다른 카테고리로 이동할 수 있고, ‘행사에 추가’로 행사 준비 목록에 가져올 수 있습니다. 보유 수량은 자동 차감하지 않습니다. 책임자는 기물 목록을 조회하고 담당 행사의 준비 목록을 관리합니다.

`케이터링 통합 관리 시스템.md`를 기준으로 구현한 한국어 행사 운영 웹앱입니다. React 화면과 Node.js·SQLite 서버를 사용합니다.

## 실행

Node.js 24 이상이 필요합니다. 프로젝트 폴더에서 실행합니다.

```powershell
npm.cmd install
npm.cmd run build
npm.cmd start
```

브라우저에서 http://127.0.0.1:3001 을 엽니다. 최초 화면에서 운영 관리자 계정을 만듭니다. 기본 비밀번호나 자동 생성된 관리자 계정은 없습니다. 이후 가입한 사용자는 관리자 승인을 받고 역할과 직원 연결을 설정해야 합니다.

개발 시 `npm.cmd run server`와 `npm.cmd run dev`를 별도 터미널에서 실행한 뒤 Vite가 출력하는 주소로 접속합니다.

## 자료와 운영

기본 데이터베이스는 `data/catering.sqlite`입니다. 서버를 중지한 상태에서 데이터 디렉터리를 복사해 수동 백업할 수 있습니다. `DB_PATH`, `PORT`, `HOST` 환경 변수로 경로·포트를 바꿀 수 있습니다. 기본 서버는 이 컴퓨터에서만 접속할 수 있습니다.

외부 공개 운영에는 HTTPS와 호스팅 구성이 필요합니다. HTTPS 배포에서는 `COOKIE_SECURE=1`을 설정해야 합니다. 개인정보 보관·삭제와 정기 백업·복구 정책은 운영 전에 결정해야 합니다.

샘플 자료 버튼은 비어 있는 작업 공간에 가상 예시를 넣습니다. 실사용 자료나 지난 행사 검증 자료가 아닙니다. 샘플을 넣은 데이터베이스와 실제 운영 데이터베이스는 별도로 사용하세요.

## 핵심 규칙

- 직원의 같은 날짜 중복 배정을 차단합니다. 부족 경고 예외 확정으로 이 제한을 풀 수 없습니다.
- 관리자가 입력한 인정 분으로만 정산합니다. 시간 반올림과 휴게 공제를 자동 적용하지 않습니다.
- 필수값 누락이나 원 미만 금액이 있는 정산은 확정하지 못합니다.
- 역할별 데이터 필터를 서버에서 적용합니다. 책임자와 운전자에게 급여 금액을 반환하지 않습니다.
- 자료 조회 후 오프라인으로 바뀌면 저장한 자료를 사용하며, 입력을 기기 큐에 보존합니다. 온라인 복구 후 서버 버전과 충돌한 입력은 관리자 확인을 거칩니다.
- 오프라인에서는 급여 확정·지급·사용자 승인·충돌 해결을 수행하지 않습니다. 로그아웃은 미전송 입력이 있으면 삭제 여부를 확인합니다.

PWA와 오프라인 앱 셸은 프로덕션 빌드에서 작동하며 HTTPS 또는 localhost 환경이 필요합니다. 기기 자료는 브라우저의 사이트 데이터에 저장되므로 공용 기기에서는 로그아웃하고 사이트 데이터를 정리하세요.

## 검증

```powershell
npm.cmd test
npm.cmd run build
```

자동 검증은 가상 데이터 기반입니다. 실제 지난 행사 3건에 대한 관리자 검토, 지급 기준 확인, 현장 입력 부담과 장기간 오프라인 사용 검증은 실제 자료와 참여자가 필요합니다. 카카오톡 연동·자동 송금·세금 신고는 구현 범위에 포함하지 않습니다.
