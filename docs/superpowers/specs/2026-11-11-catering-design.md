# 케이터링 행사 운영 시스템 설계안

상태: 검토 및 사용자 확인 대기. 제품 기준은 루트의 `케이터링 통합 관리 시스템.md` PRD v1.0이다.

## 목적과 구현 선택

종이로 관리하던 행사 일정, 직원·차량 배정, 기물 점검, 현장 기록, 급여 정산을 스마트폰에서 함께 관리한다. 실제 다중 사용자 사용을 지원하는 웹앱으로 구현한다.

검토한 방식은 브라우저 저장소만 사용하는 단일 기기 앱, 관리형 클라우드 서비스, 자체 서버와 데이터베이스 구성이다. 단일 기기 앱은 공동 작업과 서버 권한 검사를 충족하지 못한다. 클라우드 서비스는 별도 계정과 배포 설정이 필요하다. 구현자 선택은 **React·TypeScript 화면 + Node.js API + SQLite 데이터베이스**다. 현재 설치된 Node 24 환경을 사용하고 프로젝트 내부에 데이터를 저장한다. 처음에는 로컬에서 실행하며 외부 공개 배포는 별도 작업이다.

## 화면과 사용 흐름

화면은 한국어이며 모바일에서는 하단 메뉴, 넓은 화면에서는 사이드 메뉴를 사용한다. 따뜻한 흰색 배경, 짙은 녹색 강조, 명확한 상태 표시로 구성한 운영 도구다. 장식보다 일정·부족 경고·다음 할 일을 우선한다.

```text
오늘의 운영 · 날짜 선택                 행사 등록
진행할 행사 / 미확정 배정 / 준비 누락
행사 목록 → 행사 상세
             개요 | 인력·차량 | 기물 | 현장 기록
하단: 오늘 / 행사 / 직원 / 정산 / 설정
```

운영 관리자는 모든 기능에 접근한다. 책임자는 전체 행사와 근무 기록을 조회하고 담당 행사의 기물·현장 기록을 편집한다. 운전자는 자신이 운전하는 차량의 탑승 직원 명단과 연락처만 조회한다. 여러 역할이 있는 사용자는 권한을 합산하고 관리자 권한을 유지한다. 세부 편집 권한은 PRD 미정 사항에 대한 구현자 제안이다.

## 기능과 불변 조건

1. 행사: 이름, 장소, 날짜, 집결·시작·종료 시각, 예상 인원, 업무별 필요 인원, 최소 숙련자, 메모를 저장한다. 날짜와 시간은 한국 표준시로 해석한다. 취소 상태는 이력을 보존하며 취소된 행사 배정은 유효 배정에서 제외한다. 확정 배정이 있는 행사 날짜 변경은 배정 해제 후 처리한다.
2. 직원: 회사 출발/현지 구분, 연락처, 업무별 역량·경험, 관리자 지정 숙련 여부, 운전 가능한 차량 종류, 날짜별 참여 가능 여부를 관리한다. 참여 가능이 명시된 직원만 추천한다.
3. 배정: 같은 날짜의 다른 유효 행사에 이미 배정된 직원은 서버에서 차단한다. 역할·숙련·운전 조건을 고려한 설명 가능한 추천을 제공하며 관리자가 수정한다. 추천 우선순위는 필요 업무 충족 → 숙련자 충족 → 운전자 충족 → 해당 업무 경험 순으로 구현자가 제안한다. 부족 경고는 관리자가 사유를 입력해 확정할 수 있지만 동일 날짜 중복 직원은 예외 없이 차단한다.
4. 차량: 차량 종류, 운전자, 탑승 직원을 저장한다. 배정 차량마다 해당 차량을 운전할 수 있는 운전자와 탑승 정원 여부를 검사한다. 차량의 시간 중복은 경고만 하고 관리자가 확인한다. PRD상 차량 중복 차단 규칙은 미정이므로 확정 정책으로 취급하지 않는다.
5. 기물: 필요 수량·준비 수량·준비 여부·작동 상태를 각각 입력하고 부족·불량을 표시한다.
6. 현장: 현지 출근 인원과 개별 출근, 우수 근무자, 실제 손님 수, 추가 용달 메모, 직원별 실제 시각 및 짐 내리기 추가 분을 저장한다. 회사 출발 직원 탑승과 현지 출근을 별도 기록한다.
7. 정산: 실제 근무 분과 관리자 입력 인정 분을 별도로 저장한다. 시간 자동 반올림과 휴게 공제를 하지 않는다. 회사 출발 직원은 집결부터 종료까지와 해당 직원의 추가 분을 합산한다. 현지 직원은 행사 공통 시간과 개인별 수정 시각을 적용한다. 인정 분 × 시급 ÷ 60 + 운전 수당을 정수 연산으로 계산하고 원 미만이 생기면 확정을 차단한다. 시급·실제 시각·인정 분 등 필수값이 없으면 대기로 표시한다. 관리자가 확인한 인정 시간을 명시적으로 입력해야 확정 가능하다. 확정 뒤에는 해제 사유를 입력해야 수정할 수 있으며 수정 전후 값·사용자·시각·사유를 보존한다. 지급 여부는 확정된 정산에서 관리한다.

## 서버와 데이터

주요 데이터는 사용자·세션, 직원, 참여 가능 날짜, 행사·업무 요구, 배정·차량·탑승, 기물, 현장 기록, 근무 기록, 정산, 변경 이력, 충돌이다. SQLite 외래 키와 트랜잭션을 사용하며 같은 날짜 중복 배정을 서버와 데이터베이스에서 방어한다. 금액은 정수 원, 시간은 정수 분으로 계산한다.

가입 사용자는 승인 대기이며 관리자가 역할과 직원 연결을 설정한다. 최초 실행에서만 관리자 설정을 허용하고 관리자가 이미 있으면 초기 설정 API를 잠근다. 비밀번호는 소금값을 포함해 해시 저장하고 세션은 HttpOnly 쿠키로 유지한다. 각 API가 역할·담당 행사·탑승 관계를 확인한다. 책임자와 운전자 응답에는 급여 필드가 포함되지 않는다. 샘플 데이터는 명시적으로 선택해 넣는 가상 예시이며 실제 행사 검증 자료로 취급하지 않는다.

## 오프라인과 충돌

서비스 워커는 앱 정적 파일을 저장한다. 권한에 맞는 당일 행사 자료는 IndexedDB에 저장하며 화면에 저장 완료·미저장·오프라인·동기화 대기를 표시한다. 오프라인 입력은 로컬 큐에 쌓고 복구 시 같은 작업 ID로 재전송한다. 서버는 작업 ID로 중복을 막고 레코드 버전으로 충돌을 판단한다. 충돌 시 원래 서버 값과 기기 입력을 보존해 관리자에게 양쪽을 제시한다. 관리자가 하나를 선택하거나 병합한 뒤 적용한다. 로그아웃 시 해당 기기 캐시와 입력 큐의 미전송 여부를 안내하고 사용자 데이터를 정리한다. 오프라인에서는 새로운 권한 부여나 급여 확정·지급 처리를 허용하지 않는다.

## 범위와 검증

P0 기능, 가입·승인·권한, PWA 설치와 오프라인 입력·동기화를 구현한다. 카카오톡 연동은 범위가 결정되지 않았으므로 연결된 것처럼 표시하지 않는다. 자동 송금·세금 신고는 포함하지 않는다. 개인정보 보관 기간과 백업·복구 운영 정책은 결정이 필요하다.

핵심 검증은 동일 날짜 중복 배정 차단(다른 시간·관리자 예외 포함), 참여 불가 직원 제외, 업무·숙련·운전자 부족, 차량 운전자 자격, 역할별 API 응답, 12,000원 × 330분 = 66,000원, 원 미만·필수값 누락 차단, 확정 해제와 변경 이력, 오프라인 중복 전송·충돌 해결이다. 브라우저에서는 모바일/데스크톱 화면과 등록→배정→준비→현장→정산 흐름을 확인한다. 지난 행사 3건 자료가 없으므로 가상 데이터 자동 검증과 실제 관리자 수용 검증을 구분해 보고한다.

## 구현자가 정한 세부사항

상세 입력 항목, 추천 정렬, 취소 처리, 담당 책임자 편집 범위, 충돌의 레코드 단위 비교, 로컬 최초 관리자 설정은 위 설계의 제안이다. 사용자가 수정할 수 있다. 실제 운영용 배포 환경과 데이터 보관 기간은 이후 확인한다.
